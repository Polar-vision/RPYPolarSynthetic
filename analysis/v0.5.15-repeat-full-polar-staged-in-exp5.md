# v0.5.15-repeat-full-polar-staged-in-exp5

## Request

Clarify two related questions:

```text
Should the README section "Why Exp5 Currently Uses Two Alternations" be removed?

And while repeating
theta-only -> phi-only -> theta-only -> phi-only -> final joint BA
seems to have no gain,
could repeating the full staged solver
theta-only -> phi-only -> final joint BA
-> theta-only -> phi-only -> final joint BA
have gain?
```

## Short Answer

The original heading was too strong.

It is better treated as a **schedule note**, not a method-justification section.

And in the current released Exp5 setup, repeating the full staged solver also does **not** improve the final result.

## What Was Compared

Using the current released Exp5 defaults:

- same airborne scene;
- same Monte-Carlo initialization settings as `run_exp5_experiment.py`;
- dense final refinement;
- `15` staged trials total (`5` yaw levels × `3` trials);

I compared three schedules:

1. one staged cycle:

```text
theta-only -> phi-only -> final joint BA
```

2. two staged cycles inside one staged solve:

```text
theta-only -> phi-only -> theta-only -> phi-only -> final joint BA
```

3. two full staged solves in sequence:

```text
theta-only -> phi-only -> final joint BA
-> theta-only -> phi-only -> final joint BA
```

where the second full staged solve starts from the already converged result of the first one.

## Measured Results

| Schedule | Convergence | Median staged pose error | Median final pose error | Median translation error | Median structure rel. RMSE | Median nfev |
|---|---:|---:|---:|---:|---:|---:|
| one full `polar_staged` | `100.0%` | `1.628450 deg` | `0.554396 deg` | `0.306351 m` | `0.002000` | `97.0` |
| one solve with two staged cycles | `100.0%` | `1.628450 deg` | `0.554396 deg` | `0.306351 m` | `0.002000` | `101.0` |
| two full `polar_staged` solves | `100.0%` | `0.561096 deg` | `0.554396 deg` | `0.306351 m` | `0.002000` | `12.0` for the second solve |

## Interpretation

These numbers say:

- repeating `theta-only -> phi-only` inside the same staged solve does not improve the final Exp5 answer;
- repeating the **full** staged solver after the first solve also does not improve the final Exp5 answer;
- the second full solve only starts from an already excellent basin, so it converges quickly and reproduces the same final solution.

The lower staged pose error in the second full solve is not evidence of a better final optimum.

It only reflects that:

- the second solve starts from a much better initialization than the raw Monte-Carlo perturbation.

## Best Practical Reading

For the current codebase:

```text
Neither repeating theta/phi cycles nor repeating the full polar_staged solve
is the key reason Exp5 succeeds.
```

The more important success factors remain:

1. the corrected airborne geometry;
2. the staged front-end itself versus direct joint optimization;
3. and the dense final covariance-aware joint BA.

## README Consequence

So the README section should not sound like:

- "Exp5 succeeds because it uses two alternations"

It should instead sound like:

- "the current Exp5 runner happens to use this schedule, but that schedule detail is not the main scientific explanation of the result."
