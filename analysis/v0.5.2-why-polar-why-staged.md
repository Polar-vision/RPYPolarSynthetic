## Key README Messages Added

### Message 1

`polar_plain_joint` is not the final method. Its role is to isolate the geometry and expose what is still statistically wrong.

### Message 2

`polar_cov_joint` is not "polar plus some heuristic weights". It is the statistically repaired polar residual:

- propagate covariance from pixel space;
- wrap `phi`;
- gate `phi` near the optical axis.

### Message 3

`polar_staged` is not just another residual. It is a search-strategy change:

- first restrict the problem to tilt with `theta-only`;
- then restrict it to optical-axis yaw with `phi-only`;
- only then release the full joint BA state.

### Message 4

In BA experiments, freezing depth / translation / `XYZ` during staged rotation initialization is part of the method design, not a simplification accident. Otherwise those variables can absorb pose error too early.

### Message 5

Exp5's two staged alternations are now documented as a bounded engineering choice for a harder airborne block, not as a general claim that more staged cycles must always improve the result.

## Selected Q&A

### Q1

Why keep this as a text-only version?

### A1

Because the user explicitly chose to defer figure-making in this task. The immediate goal was to make the method story readable and technically accurate in the README first.

### Q2

Does this version claim that repeated staged cycles always help?

### A2

No.

It only documents the current repository design:

- Exp1-Exp4 use one staged `theta -> phi` pass;
- Exp5 uses two bounded alternations before final joint BA.

This version does not attempt to characterize the failure boundary or prove monotonic improvement with more cycles.
