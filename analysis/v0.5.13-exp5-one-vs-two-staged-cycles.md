# v0.5.13-exp5-one-vs-two-staged-cycles

## Request

Clarify:

```text
If the second theta-only has little gain,
and the second phi-only should also have little gain,
then why can Exp5 get a higher convergence rate with two staged cycles?

If one theta-only + one phi-only + final joint BA is not 100%,
what exactly is the second cycle rescuing?
```

## Short Answer

For the **current repository state**, that premise does not hold.

I reran the current `Exp5` setup with the same scene and Monte-Carlo settings used by `run_exp5_experiment.py`, changing only:

- `staged_cycles=1`
- versus `staged_cycles=2`

and obtained essentially identical results.

So, in the current code:

- the second staged cycle does **not** appear to increase convergence;
- it mainly adds a few more function evaluations;
- and it does **not** seem responsible for the reported `100%` success.

## What Was Tested

I used the current `Exp5` configuration from `run_exp5_experiment.py`:

- `trials_per_level = 3`
- `yaw_init_error_deg = [0, 30, 60, 100, 140]`
- `tilt_error_deg = 22.0`
- `translation_error_m = 0.70`
- `seed = 541`
- `staged_final_use_sparsity = False`

and compared only:

- `staged_cycles = 1`
- versus `staged_cycles = 2`

## Measured Results

### Overall

| Setting | Convergence | Median staged pose error | Median final pose error | Median translation error | Median structure rel. RMSE | Median nfev |
|---|---:|---:|---:|---:|---:|---:|
| `staged_cycles = 1` | `100.0%` | `1.628450 deg` | `0.554396 deg` | `0.306351 m` | `0.002000` | `97.0` |
| `staged_cycles = 2` | `100.0%` | `1.628450 deg` | `0.554396 deg` | `0.306351 m` | `0.002000` | `101.0` |

### Per-Yaw

For every tested yaw level:

- `0 deg`
- `30 deg`
- `60 deg`
- `100 deg`
- `140 deg`

both settings achieved:

- `100%` convergence,
- the same staged pose error medians,
- and the same final pose / translation medians to printed precision.

## Interpretation

This matches the geometry argument from the previous notes:

- the second `theta-only` pass does not get new information from updated `yaw`;
- the second `phi-only` pass also has very limited new work if the first cycle already reached essentially the same block solution;
- therefore a second cycle should not be expected to create a major basin change here.

That is exactly what the current rerun shows.

## So Why Did The Earlier Story Suggest Otherwise?

The most likely explanations are:

1. an earlier repository state had a slightly different scene / seed / initialization / solver setting;
2. the extra cycle was added as a cautious stabilization choice during development, even if it is not necessary in the current final setup;
3. the README wording over-attributed the final `100%` result to the second cycle instead of to the overall staged strategy plus the current experiment design.

## Best Current Conclusion

For the current codebase, the most defensible statement is:

```text
Exp5 reaches 100% convergence because the staged strategy as a whole places the final joint BA in the correct basin.
Under the current released Exp5 setup, using two staged cycles instead of one does not measurably improve that success rate.
```

## Practical Consequence

If we want the README to be maximally accurate, it should avoid implying:

- "the second staged cycle is what makes Exp5 succeed"

and instead say something closer to:

- "Exp5 currently uses two staged cycles as a conservative numerical schedule, but in the present setup one staged cycle already reproduces the same convergence outcome."
