# v0.5.14-exp5-success-factors

## Request

Re-examine `analysis/v0.5.0-exp5-uav-oblique-strips.md`.

The question was:

```text
The first Exp5 really failed.
But in the successful second Exp5, is the true key factor really
"two theta-only -> phi-only alternations before the final stage"?

If not, README should be corrected.
```

## Conclusion

Yes, the README needed correction.

The first failed Exp5 prototype and the successful released Exp5 do **not** differ mainly because of:

- using two staged `theta-only -> phi-only` cycles instead of one.

The more important factors are:

- the geometry redesign that avoids near-`180 deg` true `roll/pitch` under this repository's `R = Rz(yaw) Ry(pitch) Rx(roll)` convention;
- and the dense final covariance-aware joint BA used by `run_exp5_experiment.py`.

The extra staged cycle is better interpreted as:

- a conservative schedule choice,
- not the decisive reason Exp5 succeeds.

## Evidence From `v0.5.0-exp5-uav-oblique-strips.md`

That file already states the first Exp5 prototype failed mainly because:

- the cameras were physically above the scene in a standard `z-up` world;
- their optical axes therefore pointed toward negative world `z`;
- under this repository's rotation convention, that forced true downward-looking cameras into near-`180 deg` `roll/pitch`;
- staged initialization then broke for the wrong reason.

So the first major fix was geometric, not an extra staged cycle.

## Current Code-Level Verification

I reran the current released Exp5 setup using the same default settings as `run_exp5_experiment.py`:

- `trials_per_level = 3`
- `yaw_init_error_deg = [0, 30, 60, 100, 140]`
- `tilt_error_deg = 22.0`
- `translation_error_m = 0.70`
- `seed = 541`

and separated two implementation choices:

1. number of staged cycles;
2. dense vs sparse final joint BA.

## Result 1: One Cycle vs Two Cycles

Using dense final refinement:

| Setting | Convergence | Median staged pose error | Median final pose error | Median translation error | Median structure rel. RMSE | Median nfev |
|---|---:|---:|---:|---:|---:|---:|
| `1` staged cycle + dense final | `100.0%` | `1.628450 deg` | `0.554396 deg` | `0.306351 m` | `0.002000` | `97.0` |
| `2` staged cycles + dense final | `100.0%` | `1.628450 deg` | `0.554396 deg` | `0.306351 m` | `0.002000` | `101.0` |

So in the **current released setup**:

- one cycle and two cycles give the same convergence;
- the second cycle does not explain the jump to `100%`.

## Result 2: Dense Final vs Sparse Final

Holding the staged schedule fixed and changing the final joint solver:

| Setting | Convergence | Median final pose error | Median translation error | Median structure rel. RMSE | Median nfev |
|---|---:|---:|---:|---:|---:|
| `1` staged cycle + dense final | `100.0%` | `0.554396 deg` | `0.306351 m` | `0.002000` | `97.0` |
| `1` staged cycle + sparse final | `86.7%` | `0.862592 deg` | `0.463717 m` | `0.002266` | `186.0` |
| `2` staged cycles + dense final | `100.0%` | `0.554396 deg` | `0.306351 m` | `0.002000` | `101.0` |
| `2` staged cycles + sparse final | `86.7%` | `0.855957 deg` | `0.455842 m` | `0.002266` | `190.0` |

So the implementation choice that measurably changes the outcome in the current released Exp5 is:

- dense final refinement versus sparse final refinement,

not:

- one staged cycle versus two staged cycles.

## Best Interpretation

The scientifically clean reading is:

```text
The staged front-end itself is still essential:
direct joint methods fail, while staged initialization rescues the basin.

But within the released Exp5 implementation,
the extra second staged cycle is not the key reason for success.
The more important reasons are:
1. the corrected airborne geometry,
2. and the dense final covariance-aware joint BA.
```

## README Change

The README was updated accordingly to:

- stop implying that Exp5's success should be attributed mainly to the second staged cycle;
- clarify that Exp5 uses the same per-stage variable split as Exp4;
- explain that the second cycle is only a conservative schedule choice in the current runner;
- and state that the geometry redesign and dense final refinement are the more important success factors.
