# v0.5.16-exp5-staged-cycles-set-to-1

## Request

Apply three consistency fixes:

1. since `staged_cycles=2` and `staged_cycles=1` give almost the same Exp5 result, set Exp5 to `staged_cycles=1`;
2. revise the README schedule discussion so it says repeated staged init or repeated full `polar_staged` has little effect on convergence in the current setup;
3. rename `How Does polar_staged Enter The Final Joint BA?` to something more accurate, because `polar_staged` already includes the final joint BA.

## Code Change

`run_exp5_experiment.py` was updated from:

```text
staged_cycles=2
```

to:

```text
staged_cycles=1
```

This makes the released Exp5 runner consistent with the later verification:

- one staged cycle already reaches the same final Exp5 result as two staged cycles in the current setup.

## README Change 1: Rename The Handoff Section

The old section title:

```text
How Does polar_staged Enter The Final Joint BA?
```

was conceptually imprecise, because:

- `polar_staged` is the whole method,
- and it already includes the final joint BA.

The more accurate title is:

```text
How Does staged init Enter The Final Joint BA?
```

because what actually gets handed to the final joint solve is:

- the output of staged initialization.

## README Change 2: Reframe The Exp5 Schedule Note

The Exp5 note was rewritten so it no longer suggests:

- two alternations are a key reason Exp5 works.

Instead it now states the verified conclusion:

- `staged_cycles=1` and `staged_cycles=2` behave essentially the same in current Exp5;
- repeating the full staged solver also does not materially improve the final result;
- the more important ingredients are the corrected geometry, staged front-end versus direct joint BA, and dense final refinement.

## Short Interpretation

This makes the repository more internally consistent:

- the code now uses the simpler Exp5 schedule that already works;
- the README no longer over-emphasizes repeated staging;
- and the terminology now cleanly separates `staged init` from the full `polar_staged` method.
