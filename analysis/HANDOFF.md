## 0. 最重要的三句话（先读这个）

1. **本项目最诚实的结论是否定性的**：把姿态解耦为 tilt + 绕轴旋转，在**估计精度**上不带来任何优势（与 UV/三自由度最小二乘完全等价，多次独立实验证实）；在**判定层**（可行性/不可行性/边界证书）才有条件地、狭窄地有价值。
2. **"解耦"不是卖点**。报告第 3.8 节早已用二维表说明：解耦由**参数化**决定，与残差坐标无关——UV×(tilt+yaw) 一样解耦，polar×三自由度照样崩。任何"polar 解耦天然更准"的说法都被自己的实验否证。
3. **价值落点只有一处真正不可替代**：**不可行证明 + 零测度事件（相切、窄可行口袋）的精确定位**。局部求解器原理上给不出不可行证明，网格在任何分辨率下只能"没找到"而说不出"还剩多少没排除"。这是全局唯一没有被任何一轮审计削掉的东西。**9.17 之后要再加一句限定**：真实载荷公差表上，两两判据与精确判定的分歧在 3σ 约定下是 **0**、最坏口径上限 **3.3%**；13.41% 是"容差的百分比"不是"设计的百分比"。所以判定层的客户是"**吃紧的设计**"（A/σ≤2、3–4 通道），不是"任何多通道载荷"。

## 2. 分析逻辑主线（新账号必须理解的整体脉络）

### 2.1 核心数学结论（第 2–5 章）
- **商空间解耦（§2）**：`R = Rz(ψ)·Ry(p)·A`，`a = Aᵀe₃`，`θ = acos(aᵀu)` 与 ψ **精确无关**；`φ = wrap(α + ψ)`；商空间为 `H\SO(3) ≅ S²`（左乘群作用，**勿写 S²/S¹**）。
- **局部强凸（§4）**：`∇²C = JᵀWJ + Σ wᵢ eᵢ ∇²θᵢ`；零残差 + rank J=2 + cos p ≠ 0 ⇒ 正定。球面 Hess 仅作几何直觉。
- **SOC 凸表示（§4）**：`‖(I−uuᵀ)b‖ ≤ tanΘ·uᵀb`（Θ<90°），用 `cᵀb=1` 归一化。
- **关键诚实结论（§3.8）**：等距投影下 `r_px = fθ`、`φ_px = φ`，故 θ-only 最小二乘与径向像素最小二乘是**同一估计量**；解耦非 polar 独有。

### 2.2 实验证据（第 8 章）——多数是否定
- 三个消融 A1/A2/A3（§8.3）+ 第四个 A4（§8.5，噪声模型翻转）
- **A1（坐标×门控 2×2）**：极坐标不加权比 UV 更差（`14.85°` 对 `1.72°`）；白化后与 UV 同边界；增益全部来自**近轴门控**，且门控可在 UV 复现。→ polar 在 BA 内是**推导工具**，非性能来源。
- **A2/A3**：theta-only 下 3-DOF 与 2-DOF 轴误差同为 `0.047°`；差异只在条件数、规范依赖、伪逆假置信。
- **A4（§8.5）**：噪声模型翻转后，"门控=全部增益"不可直接移植；`sinθ` 连续降权更稳。
- §8.4 权重错配定理：能证 `R(α)≥1`（Gauss–Markov），但 **R 不能预测实际误差比**（形状不同：R 幂律、实测阈值）——"相图可预测成败"被自己否证。

### 2.3 判定层（第 9 章）——价值唯一所在，但也一直在收窄
- 三套原型：出光联锁（k=2 误放行 0/2400，可用率 13.7%）、星敏定姿（轴误差与闭式吻合 2.4%）、限位校验（候选集引理，完备对任意 n）。
- §9.6/9.10：补锥后"凸+Helly≤4"失效，见证无界；五个场景审下来**四个退化成点查询、一个退化成 1-D**；真正需要"存在性"的只有零测度事件定位。
- §9.11：真实规模分支（三角不等式围界，节点主要随界面长度而非约束数）。
- §9.12：astroplan 交叉校验（修了一个真 bug；月亮星历误差改口 0.3°→约 1°）。
- §9.13：真实 LLFF 下一视角 = **负结果**（网格与分支均 100%，分支无优势）。
- **§9.14（本次新增）**：三安全场景 = 价值只在小可行口袋的假阴性率 + 不可行证明，见下。

## 3. §9.14 三安全场景验证

**代码**：`src/rpy_polar_synth/safety_scenarios.py`、`run_safety_scenarios.py`、`plot_safety_scenarios.py`
**数据**：`outputs_safety/`（6 个 CSV + 1 JSON）
**图**：`analysis/figures/safety_scenarios.png`

### 统一协议（务必记住，否则会误读数据）
- YES 只由**认证点**给出（两方法都精确）；NO 只把分支**残差恰好归零**的实例当"证明"；分支的"未定残差"本身也是输出（能说"还剩多少没排除" vs 网格只能说"没找到"）。

### 三个场景结论
| 场景 | 关键数字 | 结论 |
|---|---|---|
| A 多相机/传感器布置 | 随机布置 81 例可行网格 0 误判；**小团块** 0.05°宽 0.5°网格漏 8/8、0.02°宽 0.1°仍漏 7/8；分支全 0 | 正常布置网格够用且更快；小可行口袋才有价值 |
| B 机械臂巡检规划修剪 | 网格误剪 1/30 真可行计划（0.3°勉强路点），分支 0；分支 108ms/计划 vs 网格 13.5ms | 不误剪是工程偏好而非数学独占 |
| C AI 安全外壳 | 点检验 24µs 两方法无差；**修复存在性**网格 0.5°假阴性 7.9%（3/38），分支 0；70 个不可修复提议分支全证明（多数 1 节点） | 假阴性率是安全层真正有分量的数字 |

### 净结论（写进报告 §9.14 末尾的两句话）
1. **凡"找一个可行点"，网格与分支等价甚至网格更快**（9.13 的 4254 次 + A 随机布置 + B 正常路点 + C 点检验，合计一致）。
2. **价值只在两种存在性事件**：可行域被压成**面积小于一个采样单元的小口袋**（A 团块、B 勉强路点、C 修复存在性），以及**证明"不存在"**（分支零残差证书，网格永远只能"没找到"）。

### 一个重要的方法精化（本次实验新发现）
**网格漏判由"面积"决定，不是"窄"本身。** 细长透镜（宽 0.02°、长 0.9°）网格**全不漏**——它面积足够大。小团块（直径 0.02°）才漏。这修正了此前"窄缝会被漏掉"的粗糙说法，已写进报告 §9.14 与 §9.13 的呼应处。

### 边界案例（如实报告，勿删）
2 个 `blob -0.02°` 构造不可行例，分支停在 `NO_RESIDUE`（残差 ~1e-7 sr）：两个 cap 恰好分开 0.02° 的临界构型，围界在几何奇点处收敛慢。分支**如实报告 NO_RESIDUE 而非假装证明**——这正是分支比网格多出来的东西，必须保留在数据里。

## 3c. §9.16 复制性研究（本次会话成果）

**问题**：§9.15 说"价值只落在有既有错判据的场景"，这判断本身是不是孤例？

**方法**：定义乐观系数 `rho = r* / (max_ij d_ij / 2)`，即两两公差表把每个容差少算的比例（无量纲）。真值由两条互不相关的路径给出——枚举 2 点直径/3 点外心的最小球冠，与凸程序 `max s s.t. c_i·x >= s`；125 组随机配置最大差 `5.2e-6` 度，等分环闭式 `1/sin(k*pi/n)` 吻合到 `2.3e-4`。

**结果**：

- **R1 容差失衡**：窗口单峰，`κ=1`（各通道容差相当）取峰 `13.41%`，`κ=0.5` 降到 `6.59%`，`κ≥2` 归零。**缺陷要求每条约束同时吃紧**，而那正是投产方案的常态。
- **R2 随机多通道**：`rho` 中位 `1.000–1.008`、90 分位 `1.03–1.055`、`rho>=1.05` 占 `3–12%`；通道越多缺陷越小，**最危险的是 3–4 个通道**；名义方向共线时窗口恒为零。
- **R3 五轴装夹分组（新场景）**：单链聚类＝两两判据。幻影窗口 `a/reach ∈ [0.96, 1.28]`（宽 33%，最坏少算 2 个装夹）；随机 4 面零件 **75%** 含幻影簇，平均少算 `0.84` 个。
- **R4 三传感器支架**：两两表要 `0.433`，精确要 `0.500`，`rho=1.1547`，表说可行、实际差 `0.050`，IIS 是全部三个。

**四道门**（C1 既有判据 / C2 正测度错 / C3 尺度无关 / C4 有人付钱）：八个场景**只有两个**通过——装调公差（`13.4%`）与五轴装夹分组（`33%`）；两者共用一个错误来源：**把必要条件当充分条件用**。

**两次被自己抓住的错误（务必记住）**：

1. 用锥规划（CLARABEL）判可行性，在 `κ=0.5, τ=1.54` 处报"不可行"，而 `0.005°` 网格在同一处找到裕度 `-0.72°` 的点。原因：容差几度时 `cos θ` 与 1 只差 `1e-3`，求解器绝对容差淹没信号。**已改为切平面测地凸 min-max，并逐点与网格互验。**
2. `_ang` 改为返回度之后，`random_suite` 与 `setup_grouping` 里仍写着 `* DEG`，导致最小间距小 57 倍、单链聚类几乎不合并；`min_cap_bruteforce` 的覆盖容差 `1e-12` 度比浮点误差还小，宽分布时回退到"全球面"（表现为 `excess=160°` 这种不可能的数）。**改单位时全局搜一遍 `DEG`。**

**重要技术修正（会影响 §9.14 的表述）**：纯球冠可行性是**凸问题**（`max_i(angle(x,c_i)-theta_i)` 是测地凸函数的最大值），局部下降即全局，且有对偶证书。因此"只有分支定界能证明不可行"**只对非凸情形成立**；作为一般主张是错的。产品必须按凸/非凸分流。

## 3d. §9.17 P3 回放：真实十通道公差表（本次会话成果）

**问题**：§9.16 结尾留下的 P3 待办——拿一套真实多通道载荷的公差表，看真实世界是否踩到那个 13.41% 的坑。

**数据**：NASA LRO 指向与对准规范 `431-SPEC-000113` Rev A（2007-04-06 生效，公开）。十个通道"对准到航天器基准"的角分配：NAC-L/R、WAC、LOLA、LAMP 各 `300″`，Diviner、CRaTER、LEND 各 `500″`，Mini-RF `750″`，激光测距望远镜 `36″`。CSV 在 `analysis/data/lro_alignment_allocations.csv`，每行带条款号与原文引文。**公开文件不需要脱敏；需要脱敏的那一列（实测装订偏差）恰恰是公开文件没有的。**

**模型**：一次共用安装面 = 一个平移向量 `x`，残留 `d_i - x`，问平面圆盘是否共点。与 §9.16 球面求解器在 300 组随机四通道上互验，**分歧 0 组**。

**结果**：

- **两处可核条款都对**：Table 9-3 的 NAC 对 `102″` vs `103″` 复现余量 `1″`（两通道时两两判据精确，`rho=1.000`）；LOLA-入-NAC 条款判 **UNDECIDED**，两种读法差 **1519″**（要求 5040″ + 分配 1636″ 超出半视场 5157″）。
- **分组被工具推出来**：九台甲板仪器散布 220″ 时甲板可行（余量 140″），计入 36″ 的激光测距望远镜即不可行（缺口 34″），IIS = {LAMP, 望远镜}；而文档 §12.0 写着该望远镜装在 HGA 支架上。
- **救援容量（最坏口径）**：`T/A≤1` 两判据重合且均为 1；`T/A∈[1.05,1.6]` 张开，峰 `3.3%`（`T/A=1.25`）；带外两侧一致。盲带绝对宽度：300″→80.4″、500″→134″、750″→201″。
- **3σ 生产视角**：`A/σ=3` 时两判据均 `0.998`，**1200 次抽样 0 次分歧**；唯有 `A/σ≲2` 才出现 1–1.6% 的分歧。

**裁决**：P3 的门**没过**。真实表上"与两两表相反"是 0 次；缺的不是公差表，是实测装订列与评审记录。**13.41% 是容差值的百分比，不是设计的百分比**——这句修正已写进报告 §9.17、§10.5、§10.6 与 `product-boresight.md` §1.1。

**方法要点（可复用）**：两两判据在设计盒内是**恒真**的（三角不等式：逐台全过则两两必过），它没有独立分辨力；唯一能说"不"的场合是某台已超自己的分配而垫片还想救它。这一点解释了 S3/R4 为什么能构造出 100% 的假可行，也解释了真实表为什么碰不到。

### 代码/构建坑（历史踩过，勿重蹈）
1. **写公式避免经 shell/heredoc 传反斜杠**（会变 `//`）；用 `chr(92)` 拼接，或直接用 Edit/Write 工具写文件。
2. KaTeX 链路（remark-math + rehype-katex）**只认 `$...$` / `$$...$$`**，不认 `\[ \]`、`\lVert`、`\|`、`\leftmoon`；用 `$$`、`\sqrt{u\cdot u}`、`\beta_{\rm M}`。

4. `_circle_circle_points` 圆交点：必须在正交基 `(u1,e,f)` 里解，否则 `sin²d` 系数丢有效数字导致误判。

6. `local_to_enu` 的 lon 已是弧度，勿重复乘 DEG。
7. 构造"绕 x 轴的环"要 `cosρ·x̂ + sinρ(cosα ŷ + sinα ẑ)`，勿用绕 z 轴的方位/仰角（会得到极区小圆）。
8. matplotlib 图注里 `\n` 会被替换成字面 `/n`；中文图注不显示，全部用英文。
9. **`make.sh` 里给 Chrome 的 `file://` URL 必须用 Windows 路径**：Git Bash 的 `pwd` 返回 `/e/zuo/...`，直接拼成 `file:////e/...` 会让 Chrome 报 `ERR_FILE_NOT_FOUND`——而 `stamp.py` 照样会把**上一次的** `report_raw.pdf` 盖好页码并覆盖正式 PDF，看起来“构建成功”但内容是旧的。脚本已改用 `pwd -W`，若再遇页数没变，先删 `report_raw.pdf` 再跑。
