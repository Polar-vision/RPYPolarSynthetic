## 0. 最重要的三句话（先读这个）

1. **本项目最诚实的结论是否定性的**：把姿态解耦为 tilt + 绕轴旋转，在**估计精度**上不带来任何优势（与 UV/三自由度最小二乘完全等价，多次独立实验证实）；在**判定层**（可行性/不可行性/边界证书）才有条件地、狭窄地有价值。
2. **"解耦"不是卖点**。报告第 3.8 节早已用二维表说明：解耦由**参数化**决定，与残差坐标无关——UV×(tilt+yaw) 一样解耦，polar×三自由度照样崩。任何"polar 解耦天然更准"的说法都被自己的实验否证。
3. **价值落点只有一处真正不可替代**：**不可行证明 + 零测度事件（相切、窄可行口袋）的精确定位**。局部求解器原理上给不出不可行证明，网格在任何分辨率下只能"没找到"而说不出"还剩多少没排除"。这是全局唯一没有被任何一轮审计削掉的东西。

## 2. 分析逻辑主线（新账号必须理解的整体脉络）

### 2.1 核心数学结论（第 2–5 章）
- **商空间解耦（§2）**：`R = Rz(ψ)·Ry(p)·A`，`a = Aᵀe₃`，`θ = acos(aᵀu)` 与 ψ **精确无关**；`φ = wrap(α + ψ)`；商空间为 `H\SO(3) ≅ S²`（左乘群作用，**勿写 S²/S¹**）。
- **局部强凸（§4）**：`∇²C = JᵀWJ + Σ wᵢ eᵢ ∇²θᵢ`；零残差 + rank J=2 + cos p ≠ 0 ⇒ 正定。球面 Hess 仅作几何直觉。
- **SOC 凸表示（§4）**：`‖(I−uuᵀ)b‖ ≤ tanΘ·uᵀb`（Θ<90°），用 `cᵀb=1` 归一化。
- **关键诚实结论（§3.8）**：等距投影下 `r_px = fθ`、`φ_px = φ`，故 θ-only 最小二乘与径向像素最小二乘是**同一估计量**；解耦非 polar 独有。

### 2.2 实验证据（第 8 章）——多数是否定
- 三个消融 A1/A2/A3（§8.3）+ 第四个 A4（§8.5，噪声模型翻转）
- **A1（坐标×门控 2×2）**：极坐标不加权比 UV 更差（`14.85°` 对 `1.72°`）；白化后与 UV 同边界；增益全部来自**近轴门控**，且门控可在 UV 复现。→ polar 在 BA 内是**推导工具**，非性能来源。
- **A2/A3**：theta-only 下 3-DOF 与 2-DOF 轴误差同为 `0.047°`；差异只在条件数、规范依赖、伪逆假置信。
- **A4（§8.5）**：噪声模型翻转后，"门控=全部增益"不可直接移植；`sinθ` 连续降权更稳。
- §8.4 权重错配定理：能证 `R(α)≥1`（Gauss–Markov），但 **R 不能预测实际误差比**（形状不同：R 幂律、实测阈值）——"相图可预测成败"被自己否证。

### 2.3 判定层（第 9 章）——价值唯一所在，但也一直在收窄
- 三套原型：出光联锁（k=2 误放行 0/2400，可用率 13.7%）、星敏定姿（轴误差与闭式吻合 2.4%）、限位校验（候选集引理，完备对任意 n）。
- §9.6/9.10：补锥后"凸+Helly≤4"失效，见证无界；五个场景审下来**四个退化成点查询、一个退化成 1-D**；真正需要"存在性"的只有零测度事件定位。
- §9.11：真实规模分支（三角不等式围界，节点主要随界面长度而非约束数）。
- §9.12：astroplan 交叉校验（修了一个真 bug；月亮星历误差改口 0.3°→约 1°）。
- §9.13：真实 LLFF 下一视角 = **负结果**（网格与分支均 100%，分支无优势）。
- **§9.14（本次新增）**：三安全场景 = 价值只在小可行口袋的假阴性率 + 不可行证明，见下。

## 3. §9.14 三安全场景验证（本次会话的最终成果）

**代码**：`src/rpy_polar_synth/safety_scenarios.py`、`run_safety_scenarios.py`、`plot_safety_scenarios.py`
**数据**：`outputs_safety/`（6 个 CSV + 1 JSON）
**图**：`analysis/figures/safety_scenarios.png`

### 统一协议（务必记住，否则会误读数据）
- YES 只由**认证点**给出（两方法都精确）；NO 只把分支**残差恰好归零**的实例当"证明"；分支的"未定残差"本身也是输出（能说"还剩多少没排除" vs 网格只能说"没找到"）。

### 三个场景结论
| 场景 | 关键数字 | 结论 |
|---|---|---|
| A 多相机/传感器布置 | 随机布置 81 例可行网格 0 误判；**小团块** 0.05°宽 0.5°网格漏 8/8、0.02°宽 0.1°仍漏 7/8；分支全 0 | 正常布置网格够用且更快；小可行口袋才有价值 |
| B 机械臂巡检规划修剪 | 网格误剪 1/30 真可行计划（0.3°勉强路点），分支 0；分支 108ms/计划 vs 网格 13.5ms | 不误剪是工程偏好而非数学独占 |
| C AI 安全外壳 | 点检验 24µs 两方法无差；**修复存在性**网格 0.5°假阴性 7.9%（3/38），分支 0；70 个不可修复提议分支全证明（多数 1 节点） | 假阴性率是安全层真正有分量的数字 |

### 净结论（写进报告 §9.14 末尾的两句话）
1. **凡"找一个可行点"，网格与分支等价甚至网格更快**（9.13 的 4254 次 + A 随机布置 + B 正常路点 + C 点检验，合计一致）。
2. **价值只在两种存在性事件**：可行域被压成**面积小于一个采样单元的小口袋**（A 团块、B 勉强路点、C 修复存在性），以及**证明"不存在"**（分支零残差证书，网格永远只能"没找到"）。

### 一个重要的方法精化（本次实验新发现）
**网格漏判由"面积"决定，不是"窄"本身。** 细长透镜（宽 0.02°、长 0.9°）网格**全不漏**——它面积足够大。小团块（直径 0.02°）才漏。这修正了此前"窄缝会被漏掉"的粗糙说法，已写进报告 §9.14 与 §9.13 的呼应处。

### 边界案例（如实报告，勿删）
2 个 `blob -0.02°` 构造不可行例，分支停在 `NO_RESIDUE`（残差 ~1e-7 sr）：两个 cap 恰好分开 0.02° 的临界构型，围界在几何奇点处收敛慢。分支**如实报告 NO_RESIDUE 而非假装证明**——这正是分支比网格多出来的东西，必须保留在数据里。

### 代码/构建坑（历史踩过，勿重蹈）
1. **写公式避免经 shell/heredoc 传反斜杠**（会变 `//`）；用 `chr(92)` 拼接，或直接用 Edit/Write 工具写文件。
2. KaTeX 链路（remark-math + rehype-katex）**只认 `$...$` / `$$...$$`**，不认 `\[ \]`、`\lVert`、`\|`、`\leftmoon`；用 `$$`、`\sqrt{u\cdot u}`、`\beta_{\rm M}`。
3. **worktree 的 PDF 常被预览面板锁定**（`os.replace` 报 WinError 5），改完 md 后 PDF 可能无法覆盖——交付用带页数后缀的新文件名（如 `_69p.pdf`）。
4. `_circle_circle_points` 圆交点：必须在正交基 `(u1,e,f)` 里解，否则 `sin²d` 系数丢有效数字导致误判。
5. 分支枚举**必须向量化**（逐节点 Python 循环比批量慢 39 倍）。
6. `local_to_enu` 的 lon 已是弧度，勿重复乘 DEG。
7. 构造"绕 x 轴的环"要 `cosρ·x̂ + sinρ(cosα ŷ + sinα ẑ)`，勿用绕 z 轴的方位/仰角（会得到极区小圆）。
8. matplotlib 图注里 `\n` 会被替换成字面 `/n`；中文图注不显示，全部用英文。
