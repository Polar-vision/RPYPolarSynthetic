# v0.5.12-second-theta-is-mostly-extra-optimization-budget

## Request

Clarify:

```text
Does the second theta-only stage basically mean
"just a few more iterations"?
```

## Short Answer

Yes, roughly speaking.

In this repository's current setup, the second `theta-only` stage is best understood as:

- giving the staged front-end a bit more optimization budget,
- or restarting the block-coordinate process for another short cycle,

rather than introducing new geometry or new information.

## More Precise Statement

It is **not exactly** the same as:

```text
just increase iterations inside one theta-only solve
```

because the actual schedule is:

```text
theta-only -> phi-only -> theta-only -> phi-only
```

So it is better described as:

- one more staged block-coordinate cycle,
- with solver restart effects,
- finite iteration budgets per block,
- and one more chance for the later `phi-only` step to polish after the first cycle.

## Why This Is Only "Mostly" Extra Iteration Budget

The key asymmetry is:

- `theta-only` does not use `yaw`;
- `phi-only` does use the current `roll/pitch`.

Therefore:

- the second `theta-only` pass itself gets almost no new information from the previous `phi-only` pass;
- but the whole second cycle can still help a bit if the first cycle did not fully converge numerically.

So:

- geometrically, the gain is very limited;
- numerically, there can still be small practical benefit.

## Best One-Sentence Interpretation

```text
The second theta-only stage is mostly a numerical re-optimization / restart effect,
not a new yaw-conditioned theta correction mechanism.
```
