## Request

Clarify the `Experiment 5 airborne block` row in the README table under `What Exactly Is Optimized In Each Stage?`

The concern was:

```text
Does
"same as Exp4, but with one extra theta-only -> phi-only alternation before the final stage"
mean Exp5 runs polar_staged twice?

Or is the correct interpretation:
it runs two theta-only -> phi-only staged initialization cycles,
then only one final joint BA?
```

## Conclusion

The correct interpretation is:

- Exp5 does **not** run full `polar_staged` twice;
- Exp5 runs **one** `polar_staged` solve;
- inside that solve, it performs **two** staged `theta-only -> phi-only` cycles;
- then it performs **one** final covariance-aware joint BA.

So the more precise wording is:

```text
two staged theta-only -> phi-only cycles before the single final joint BA
```

not:

```text
run polar_staged twice
```

## Code Evidence

In `src/rpy_polar_synth/free_xyz_ba_experiment.py`:

- `optimize_free_xyz_staged(..., staged_cycles: int = 1, ...)` defines the staged solver;
- the loop `for cycle_idx in range(staged_cycles):` repeats the restricted `theta` and `phi` sub-solves;
- after that loop finishes, the code builds one `staged_x`;
- then it runs one final joint `least_squares(...)` refinement from that staged state.

So the structure is:

```text
repeat staged theta/phi cycle N times
-> assemble one staged initialization
-> run one final joint BA
```

## Why The Original README Wording Was Ambiguous

The old table text:

```text
same as Exp4, but with one extra theta-only -> phi-only alternation before the final stage
```

is not mathematically wrong, but it is easy to over-read as:

- "do the whole staged method once more"

which is not what the code does.

The actual difference from Exp4 is narrower:

- Exp4 uses one staged cycle:
  `theta-only -> phi-only -> final joint BA`
- Exp5 uses two staged cycles:
  `theta-only -> phi-only -> theta-only -> phi-only -> final joint BA`

## README Change

The table and nearby explanation were tightened to make this distinction explicit:

- Exp5 runs `2` staged `theta-only -> phi-only` cycles;
- there is still only `1` final joint BA;
- so this is one `polar_staged` solve with a longer staged front-end, not two complete `polar_staged` runs.

## Short Interpretation

If we define:

```text
polar_staged =
  staged theta/phi front-end
  + final covariance-aware joint BA
```

then Exp5 is:

```text
polar_staged with staged_cycles = 2
```

not:

```text
polar_staged + polar_staged
```
