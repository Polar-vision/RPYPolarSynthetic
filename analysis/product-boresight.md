# 产品设计：Boresight —— 多通道指向可行性与容差分配证书

> 状态：设计稿，基于 §9.15/§9.16/§9.17 已跑通的代码与数据。
> 一条纪律：本文所有数字都印自 `demo_boresight.py`、`run_replication.py` 与 `run_p3_replay.py`，没有一个手填。
> **§9.17 之后的一条修正**：13.41% 是"容差的百分比"，不是"设计的百分比"。在真实十通道载荷表上，两两判据与精确判定在 $3\sigma$ 约定下 **1200 次抽样 0 次分歧**，最坏口径下分歧上限 **3.3%**。所以"这个判断在结构上就是错的"应读作"**在这个方案恰好吃紧时是错的**"——见 §1.1。

## 1. 一句话与客户问句

**一句话**：给一套"多个通道必须共用一个姿态"的系统，回答**"这组容差到底能不能装出来"**，并给出**可人工复核的证书**与**三条修复路径的价目**。

**客户问句**（设计评审上真实出现的那句）：

> "相机 ±0.35°、激光 ±0.5°、雷达 ±0.45°，支架共用一个安装面——**这套公差能装出来吗？**"

现在的回答方式是一张两两公差表：每两对都在容差和以内，于是判"能"。**这个判断在结构上就是错的**，错多少有闭式：等容差时少算 13.41%，最坏情形见 §9.16 表 R1。

### 1.1 但先看一件事：这个错什么时候才发作（§9.17）

§9.17 拿 LRO 的真实十通道指向规范（`431-SPEC-000113` Rev A，公开）做了一次回放。结论对销售话术是硬约束：

| 问题 | 答案 |
|---|---|
| 真实表上两两判据与精确判定分歧多少 | $A/\sigma=3$（规范自己声明的 3σ）时 **0.0000**；最坏口径上限 **3.3%**（$T/A=1.25$） |
| 13.41% 指什么 | **容差值的 13.41%**，不是设计的 13.41%。对 300″ 分配即 **80.4″** 的缝 |
| 什么时候才发作 | 装订散布落在分配的 **1.0–1.6 倍**，且通道数 3–4、各通道分配彼此相当 |

所以客户的问句要改一个字：不是"这套公差能不能装出来"，而是"**这套公差离极限有多近**"。三条五分钟筛子（分配是否 ≥2.5σ、通道数是否 ≥5、是否存在"一个安装面、一次垫片"的约束）跑完，才知道这一单值不值得接。真实表上仍然值钱的是另外两张卡：**不可行子集**与**口径裁决**——这两张不依赖 13.41%。

## 2. 为什么这件事现在能做成产品

整套问题可以塌缩成**一个比较**：

$$r^\*=\max_{x\in S^2}\ \min_i\ \angle(x,c_i)\ \le\ \min_i\theta_i$$

- $r^\*$ **只由几何决定**，与任何容差无关，且由 2 个或 3 个通道钉住（"支撑集"）。
- $\min_i\theta_i$ **只由规范决定**，与几何无关。

因此一次评审被拆成两个互不干扰的独立问题，而且两边都能给出**人能复核的**结论：

| 输出 | 形式 | 谁看得懂 |
|---|---|---|
| $r^\*$ | 一个角度，外加 2–3 个通道名 | 结构/光学工程师 |
| 支撑集 | "就是这三个钉住的" | 评审主席 |
| 缺口 | $r^\*-\min\theta_i$，正数即不可行 | 项目经理 |
| 修复菜单 | 每个选项的度数代价 | 管钱的人 |

**这是产品的全部护城河所在**：不是算法（见 §9 风险），而是**把"不可行"变成一个可签字的三行结论**。评审需要的不是求解器，是一张能放进 PPT、且经得起追问的纸。

## 3. 五张输出卡片

### 卡片 1｜Verdict
`FEASIBLE` / `INFEASIBLE` / `UNDECIDED`（只有在混入 keep-out 锥等非凸约束时才可能出现第三种）。三分法是硬要求：`UNDECIDED` 必须附带剩余面积，不能伪装成 NO。

### 卡片 2｜$r^\*$ 与支撑集
一个角度 + 2–3 个通道索引 + 钉住类型（直径 / 外心）。这三个通道就是"要动就动它们，动别的没用"。

### 卡片 3｜IIS（最小不可行子集）
贪心删除得到的最小冲突集。实测在 R4 上就是全部三个，缺口 0.050°；在 8 通道算例上是三个 0.60° 通道。**这一张是产品相对"求解器"的核心差异**：求解器说"不可行"，IIS 说"是这三个"。

### 卡片 4｜修复菜单（带价目）
三条路径，全部用同一个求解器算出来：

- **A 收紧**：把支撑集收到 $r^\*$。代价 = 加工精度等级。
- **B 改名义**：把某个支撑通道内移 $\delta$，使 $r^\*\le\min\theta$。$\delta$ 是二分出来的，只在毛坯未加工时可用。
- **C 认账**：接受缺口，逐台标定。代价 = 单台标定工时 × 批量。

R4 算例：A = 收到 0.500°；B = 相机内移 **0.177°**；C = 每台标定 0.050°。

### 卡片 5｜灵敏度（谁在浪费钱）
对每个通道算"缺口"，即 $r^\*-\theta_i$：

```
star tracker A   spec 0.25  deficit +0.618
star tracker B   spec 0.25  deficit +0.618
laser terminal   spec 0.25  deficit +0.618
imager           spec 0.60  deficit +0.268
SWIR             spec 0.60  deficit +0.268   <- sets r*
radiometer       spec 0.60  deficit +0.268   <- sets r*
beacon           spec 0.60  deficit +0.268
coarse sun sensor spec 0.60  deficit +0.268   <- sets r*
```

**这里有一个反直觉、但必须写进产品文案的事实**：$r^\*$ 与容差无关，所以**收紧任何一条通道都不可能让不可行的方案变可行**——收紧只会缩小可行集。工程界"超差了就收紧"的反射在这类问题上是**方向性错误**。能动的只有两头：把名义挪近（降 $r^\*$），或把最紧的那条放宽（抬 $\min\theta$）。

这一条本身就值一次评审的时间。

## 4. 算法内核与证书

### 4.1 三种情形，三种解法

| 可行集形态 | 解法 | 证书 |
|---|---|---|
| 纯球冠交（容差、可达方向） | 最小包围球冠：枚举 2 点直径 / 3 点外心，取最小 | 支撑集 2–3 个通道 + $r^\*$ |
| 球冠交 + 不等容差 | 切平面测地凸 min-max，局部下降即全局 | 最优点 $x^\*$ + 各通道裕度 |
| 混入 keep-out 锥（太阳/月球/羽流/禁区） | 分支围界（沿用本项目 §9.14 的机器） | 零残差或剩余面积 |

**关键取舍**：前两种情形**不需要**分支定界。$f(x)=\max_i(\angle(x,c_i)-\theta_i)$ 是测地凸函数的最大值，仍凸，局部极小即全局极小。这既是正确性论证，也是性能论证——一次凸下降，微秒级。

**这同时修正了 §9.14 的一句强主张**："局部求解器原理上给不出不可行证明"。对**非凸**情形成立；对**凸**情形不成立——凸问题的不可行性有对偶证书（Farkas）。产品必须按情形分流，否则会在客户那里被一句话问倒。

### 4.2 一次踩过的坑，写进设计约束

锥规划（SOCP）在这个量级上**不可用**：容差只有几度时 $\cos\theta$ 与 1 只差 $10^{-3}$，求解器绝对容差把信号淹没。实测在 κ=0.5、τ=1.54 处报"不可行"，而 0.005° 网格找到裕度 −0.72° 的点。

> **设计约束 D1**：任何"不可行"结论，必须由一个与主求解器**独立**的实现复核；两者不一致时，输出 `UNDECIDED`，不输出 NO。

这条约束的代价是每次判定多算一遍，收益是**永远不会给客户一个错的"没有"**。对一个用于放行的工具，这是唯一正确的取舍。

### 4.3 性能

参考实现（纯 Python，O(n⁴) 枚举）：

| n | 3 | 6 | 12 | 24 |
|---|---|---|---|---|
| 单次判定 | 0.27 ms | 4.1 ms | 45.9 ms | 489 ms |

产品化：Welzl 式随机增量（期望 O(n)）+ 编译实现，n≤32 应进入 10 µs 量级；n 到几百（星表级）应进入 1 ms。**这是工程工作，没有研究风险**。

## 5. 系统架构

```
[输入层]                        [内核]                    [输出层]
 CSV / JSON 通道表   ─┐
 SolidWorks/Creo/NX  ─┼→ 模型校验 → 精确判定 ─┬→ 证书 JSON
 Zemax/Code V 导出   ─┤   (单位/归一/退化)      ├→ 评审单页 PDF
 PLM 属性 (公差)      ─┘                        └→ CI 断言 (exit code)
                                ↓
                        修复菜单求解器（二分/梯度）
```

四个必须做对的接口细节：

1. **单位与归一**：所有输入强制转单位向量 + 度；拒绝非单位输入而不是静默归一（静默归一会掩盖 CAD 导出错误）。
2. **退化检测**：两点重合、三点共线、容差 ≥ 90° 都要单独报，不能落进通用分支。
3. **可追溯**：证书里带输入哈希 + 求解器版本 + 两种求解器的一致性余量。这是评审签字的前提。
4. **CI 断言**：`boresight check design.json --assert feasible` 返回非零退出码，让"公差漂了"在提交时就被拦住，而不是在 AIT 现场。

## 6. 开发步骤（每步都有退出判据）

### P0 冻结模型（2 周）
- 交付：`spec.md`（输入 schema、判据定义、三分法语义）、`golden/` 20 个手算可核的用例（含 R4）。
- **退出判据**：20 个用例的 $r^\*$ 与手算/闭式一致到 1e-6；R4 复现 0.433 / 0.500 / 0.050 三个数。

### P1 内核 + 双实现（4 周）
- 交付：`solve.py`（枚举 + 凸下降 + 分支三路分流）、`crosscheck.py`（独立实现）、CLI。
- **退出判据**：10⁴ 组随机配置上两实现最大差 < 1e-5 度；任何不一致必须落在 `UNDECIDED`。
- **退出判据（性能）**：n=3 的 p99 < 1 ms（Python），n=32 < 50 ms。

### P2 证书与报告（3 周）
- 交付：证书 JSON schema、单页 PDF、修复菜单求解（A/B/C 三路）。
- **退出判据**：任意一个不可行输入，PDF 上必须同时出现"缺口度数 + 支撑集 + 三条修复路径的度数代价"，且三条路径都被求解器验证过（A/B 修复后 `FEASIBLE`）。

### P3 两个真实案例回放（6 周，最关键）
- 案例 1：一套真实多通道载荷的 BOM + 公差表（从合作方拿，脱敏）。
- 案例 2：一个真实五轴零件的特征法向 + 装夹方案（用 §9.16 R3 的判据审 CAM 输出）。
- **退出判据**：至少一个案例上，工具给出的结论与"实际装配结果"一致，且**与当时的两两表结论相反**。做不到这一条，产品假设不成立，应停止而不是继续开发。

> **回放状态（§9.17，2026-10-31）**：案例 1 的**公开部分**已跑完——LRO 的十通道分配表（36″–750″，逐条有出处），配对可核条款复现 Table 9-3 的 1″ 余量，LOLA-入-NAC 判 UNDECIDED 并算出 1519″ 口径差，不可行子集把激光测距望远镜从仪器甲板上摘出来（文档本来就把它装在 HGA 支架上）。**但"与两两表相反"这一条在真实表上是 0 次**：3σ 约定下 1200 次抽样无分歧，最坏口径 3.3%。
> 结论：**门未过，且不是再找一张表能过的**。缺的是公开文件永远不会有的两列——每台仪器的实测装订偏差、评审当时用的判据。案例 1 的剩余工作全部是"拿到一列实测数"；案例 2 同理，需要一份真实的特征法向与装夹方案。

### P4 集成（8 周）
- CAD 插件（先做 SolidWorks，选它是因为 API 最省事）、Excel 插件（公差表就在 Excel 里，这是最容易被采纳的入口）。
- **退出判据**：工程师在不动原始 CAD 的前提下，5 分钟内从一张公差表得到证书。

### P5 认证与规模化（持续）
- 若进航空航天：出 V&V 报告（需求—用例—结果三段式），工具按 DO-178C 的"非机载工具"处理即可，不需要 A 级鉴定；重点是**可复现性**（同输入同输出、版本可追）。
- 若进汽车：IATF 16949 体系下作为"设计验证工具"，需给出与实测的比对报告。

**总周期**：P0–P3 约 15 周可到"能拿真实案例说话"；P4 再 8 周。

## 7. 验证计划（怎么证明它没错）

| 层次 | 方法 | 通过标准 |
|---|---|---|
| 算法正确性 | 双独立实现互验 | 差 < 1e-5 度，10⁴ 例 |
| 算法正确性 | 闭式族（等分环） | ρ = 1/sin(kπ/n)，误差 < 1e-3 |
| 数值稳健性 | 0.001° 网格对撞 | 任何分歧必须复现并解释 |
| 模型正确性 | 蒙特卡洛：按容差分布抽样装配 | 预测可行率与 MC 差 < 2% |
| 工程正确性 | 真实案例回放（P3） | 与实测一致，且与两两表相反 |

第四条最容易被跳过，也最容易致命：**几何可行 ≠ 装得出来**。真实装配还有热、应力释放、拧紧顺序、胶层厚度——本项目 §9.15 已经把这些列为未验证项。产品必须明确声明"本工具判定的是几何可行性，不含热/力/工艺漂移"，否则第一次现场偏差就会摧毁信誉。

## 8. 商业模式

> 本节的价格与路径见 `ip-moat-and-publication.md` §1–§2。那两份文档有一处结论冲突，以新的为准：**"B 席位授权"应停做**——真实使用频率是"每两年一次"（一个型号的指向评审一辈子做 1–2 次），撑不起席位假设的"每月都用"。理由不是渠道，是频率。

### 四条路径

| 路径 | 形态 | 单价（量级假设，需核实） | 周期 | 适合度 |
|---|---|---|---|---|
| **A 引擎授权给 CAE/CAM 厂商** | SDK / OEM | 一次性 ¥80–300 万 + 版税 | 12–18 月 | **首选** |
| B 席位授权（独立工具） | 桌面/插件 | ¥2–6 万/席/年 | 6 月 | 次选 |
| C 单项目评审服务 | 交付报告 | ¥15–40 万/项目 | 立即 | **先做这个** |
| D 开源核心 + 商业版 | 双许可 | 捐赠/支持 | 长 | 不推荐 |

**为什么 A 是首选**：几何本身是经典结果（§9.16、`novelty-assessment.md`），单靠算法守不住。但"证书 + 评审单页 + IIS + 修复菜单"这套工作流，对一个已有公差分析产品的厂商是**现成模块**，他们缺的正是"三行结论"这个形态。卖引擎给他们是把技术塞进现有渠道，比自建销售快 3 倍。

**为什么 C 必须先做**：它是唯一能在 3 个月内产生现金流、同时拿到真实案例（P3 的输入）的路径。没有真实案例，A 和 B 都无从谈起。

### 定价逻辑（不是拍脑袋，是可推的）

席位定价锚在替代品上：商用公差分析软件（Cetol 6σ、3DCS、VSA 一类）的席位通常在 **$10k–25k/席**量级。本产品只解一个子问题，但解得更硬（有证书），定位在 **$3k–8k/席** 是合理区间——即"母产品的 1/3 价格、1/10 的功能面"。

服务定价锚在**一次 AIT 不符合项的代价**上：空间载荷一次 AIT 返工的代价在 **¥30–100 万**量级（拆装 + 复测 + 进度）。收 ¥15–40 万做一次评审，只要拦下一次就回本。

### 市场规模（诚实版）

- 全球每年新研光电载荷/多通道指向系统：**数百套**量级。
- ADAS Tier-1：**数十家**，每家有多个平台。
- 五轴/CAM：客户是软件厂商（个位数）或大型车间（数百家）。

**这是一个千万级人民币的市场，不是十亿级。** 合理的期望是 3 年做到 20–50 席 + 5–10 个项目，年收入 **¥300–800 万**。它养得活一个小团队，撑不起一轮 VC。若目标是后者，必须换赛道（见 §10）。

## 9. 生产力换算：钱具体从哪来

### 模型 1｜省掉一次 AIT 返工（项目型客户）

一次"装不上"的返工 = 拆 + 修 + 复测 + 进度。按 ¥30–100 万/次、发生率 10–20%（行业里"公差分析没做透"的典型比例，需用客户数据校准）：

> 年 5 个项目 × 15% × ¥60 万 ≈ **¥45 万/年**

工具费（¥15–40 万/项目）与收益同量级，成交逻辑是"保险"而非"投资回报"。

### 模型 2｜取消逐台标定（量产型客户）

若设计本身闭合且有余量，则不需要逐台 boresight 标定。按每台 10 分钟、¥2/分钟、年产 10 万台：

> 10 min × 10 万台 = 16.7 万分钟 ≈ **¥33 万/年**（仅人工，不含工位与节拍损失）

**这一条是本产品最硬的 ROI**，因为它把"0.05° 的几何缺口"直接换算成"每台一次标定"。

### 模型 3｜放宽不必收紧的通道（设计型客户）

8 通道算例给出可直接用的结论：$r^\*=0.868°$ 由三个 0.60° 通道钉住，而三条 0.25° 通道**本来就装不出来**。反过来，若几何改成 $r^\*=0.30°$，则其余五条 0.60° 通道可以按工艺默认值（更便宜）走。

加工成本对公差是非线性的：从 ±0.45° 放到 ±0.6°，支架从"精镗 + 三坐标全检"降到"一次装夹加工 + 抽检"，单件成本常降 **30–50%**。这条收益最难量化，但往往是客户最愿意听的那条。

### 模型 4（R3 场景）｜少算的装夹

§9.16：75% 的随机 4 面零件会被单链聚类少算装夹，平均 0.84 个。按 2 小时/装夹、¥300/小时、年产 500 件：

> 0.75 × 500 × 0.84 × 2 × 300 ≈ **¥19 万/年/车间**

## 10. 风险（五条，按杀伤力排序）

1. **校准可以吸收一切。** 现实中多传感器是"装完再标定"，0.05° 的几何缺口会被标定吃掉。**这是最致命的反对意见。**
   → 应对：把产品定位从"能不能装"改成"**要不要为每一台付标定费**"。几何闭合 = 免标定 = 省工时；几何不闭合 = 标定 = 花钱。问题从"可行性"变成"成本"，反对意见消失（见模型 2）。对**不可标定**的系统（单体光具座、共口径、共云台）则直接成立。
2. **数学是经典结果，守不住。** 最小包围球冠有 O(n) 算法与开源实现；两两≠三者是教材级 Helly 事实；装夹规划=集合覆盖=NP-hard 在 1990 年代文献里就有。
   → 应对：不主张算法，主张**证书形态与工作流**；优先走 OEM 授权（把技术塞进别人的护城河），而不是自建壁垒。
3. **"几何可行"不等于"装得出来"。** 热、应力、胶层、拧紧顺序都不在模型里。
   → 应对：产品文案第一句就声明边界；P3 必须做真实案例回放，用实测校准模型，而不是用模型解释实测。
4. **样本太少。** 目前所有数字来自构造算例与理想化模型（§9.16 局限 1–3）。
   → 应对：P3 的两个真实案例是 go/no-go 关口；做不到就停，不要靠加功能掩盖。
5. **单客户依赖。** 项目型收入天然集中在少数几个客户。
   → 应对：先做 C（服务）验证需求，再做 A（授权）摊薄；不做 B（席位）直到有 10 个以上付费用户。

## 附：这个产品不做什么

- 不做通用公差分析（RSS/蒙特卡洛/三维公差链）——那是 Cetol/3DCS 的地盘，且他们做得更好。
- 不做位姿估计、不做标定算法、不做 SLAM——§9.13 已逐条证伪。
- 不做"更快的网格搜索"——没有客户为速度付钱，只为结论付钱。
- 不做云端 SaaS 首发——客户的数据是型号图纸，不可能上传；先做本地/离线。
