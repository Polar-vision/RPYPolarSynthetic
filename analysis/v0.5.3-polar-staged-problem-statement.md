# v0.5.3-polar-staged-problem-statement

## Request

Continue refining the README method-introduction chapter by adding a dedicated subsection:

```text
What problem does polar_staged actually solve?
```

## Why This Was Needed

After `v0.5.2`, the README already explained:

- why the method evolves from `uv_joint` to `polar_staged`;
- how staged optimization works mechanically;
- which variables are frozen in different BA regimes.

But one conceptual ambiguity still remained:

- readers could still mistake `polar_staged` for a method that mainly solves the optical-axis singularity;
- or think it is only a trick that helps when the initial `yaw` error is large.

This version sharpens that distinction.

## What Changed

Added a new subsection inside `README.md`:

```text
### What Problem Does polar_staged Actually Solve?
```

This subsection now states explicitly:

- `polar_staged` is **not** primarily solving the optical-axis singularity;
- the singularity issue is already handled inside the covariance-aware polar residual through:
  - `phi` wrapping,
  - propagated polar covariance,
  - optical-axis gating.

Instead, the subsection explains that `polar_staged` mainly solves:

- bad initialization under strong coupling;
- wrong-basin entry in direct joint optimization;
- early absorption of pose error by coupled BA variables such as:
  - depth / inverse depth,
  - translation,
  - free `XYZ` structure.

## Key Clarification Added

The new README text now draws this distinction explicitly:

- `polar_cov_joint` makes the polar residual statistically usable;
- `polar_staged` makes the optimization path more robust in coupled BA.

That is the most important conceptual separation in the whole method story.

## Why The New Text Matters

Without this clarification, a reader might incorrectly conclude one of the following:

1. `polar_staged` is just a singularity fix.
2. `polar_staged` only helps because the experiments use large initial yaw errors.
3. `polar_staged` is simply another residual variant like `polar_cov_joint`.

The new subsection counters all three interpretations.

It explains that large initial yaw error is mainly the **chosen stress axis** in the experiments, while the deeper mechanism is:

```text
bad pose initialization
-> direct joint BA lets coupled variables absorb the error
-> optimizer enters the wrong basin
-> staged search isolates pose recovery before full coupling is released
```

## Scope Decision

This version still does **not** add:

- new figures;
- new boundary experiments;
- new numerical sweeps.

It is a conceptual README clarification only.

## Selected Q&A

### Q1

Does this new subsection change the claimed role of `polar_cov_joint`?

### A1

No.

It actually makes the role of `polar_cov_joint` cleaner:

- `polar_cov_joint` repairs the residual statistically;
- `polar_staged` repairs the search path under coupling.

### Q2

Does this subsection claim that staged optimization helps in every bad-initialization scenario?

### A2

No.

It only clarifies what kind of problem the repository is targeting:

- coupled BA problems where direct joint optimization can mis-explain pose error through other state variables.
