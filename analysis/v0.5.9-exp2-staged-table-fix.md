# v0.5.9-exp2-staged-table-fix

## Request

Clarify whether the `Experiment 2` row in the README table under `What Exactly Is Optimized In Each Stage?` is accurate.

The specific concern was:

```text
For Experiment 2, is
"optimize pose rotation only, fix inverse depths"
too broad?
Should it instead say
"optimize roll/pitch, fix yaw"?
```

## Conclusion

Yes. The original README wording was too broad.

For `Experiment 2`, the `theta-only` stage does **not** optimize all pose rotation variables.

It specifically:

- optimizes `roll/pitch`,
- keeps `yaw` fixed,
- and also keeps inverse depths fixed.

So the more accurate README wording is:

```text
optimize roll/pitch, fix yaw and inverse depths
```

## Code Evidence

In `src/rpy_polar_synth/ba_experiment.py`:

- `params0, log_inv0 = unpack_ba(initial_x)` first saves the initial pose and inverse depths;
- `theta_stage(roll_pitch)` rebuilds the pose as
  `[roll_pitch[0], roll_pitch[1], params0[2]]`,
  which means `yaw = params0[2]` stays fixed;
- the packed state is `pack_ba(params, log_inv0)`,
  which means inverse depths stay fixed during this stage.

## README Change

The table row was corrected from:

```text
optimize pose rotation only, fix inverse depths
```

to:

```text
optimize roll/pitch, fix yaw and inverse depths
```

For consistency, the paired `phi-only` text is now also written explicitly as:

```text
optimize yaw, fix updated roll/pitch and inverse depths
```

## Short Interpretation

This wording matters because the staged story in `Experiment 2` is not:

- "first optimize all rotations, then optimize yaw again"

It is:

- first use `theta-only` information to correct tilt-like components (`roll/pitch`);
- then use `phi-only` information to correct optical-axis yaw;
- only after that release the full BA state.

That is the actual logic implemented by the solver.
